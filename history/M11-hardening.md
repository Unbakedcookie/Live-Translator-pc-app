## 2026-10-18 — T111 (part): failure paths in the speech and translation workers
- Reviewed against spec §9. Gaps found and fixed:
  - **Speech worker crash outside a decode** (e.g. a bug in the voice-activity step) ended the thread silently: speech just stopped. Now it restarts once ("Speech recognition hit an error and restarted.", half-finished lines dropped, streams reset to "now"), and a second crash ends with an ERROR status.
  - **Decodes failing every time** (e.g. the GPU driver crashed) only logged warnings — the user saw nothing. Now 5 failures in a row raise "Speech recognition keeps failing…", cleared automatically when decoding works again.
  - **Real bug found while testing that:** a failed partial decode left the job "not yet decoded", so the worker picked it again immediately, forever — a **100 % CPU retry loop** whenever decoding is broken (the test hung, which is how it showed). A failed partial now counts as tried until the next update interval.
  - **CPU fallback was silent.** After loading, the status now says when speech runs on the processor (no NVIDIA card, or the card failed: "…runs on the processor with a smaller model (slower, a little less accurate)").
  - **Translation worker:** an unexpected (non-engine) error ended its thread; now it's logged, reported for that line, and the worker carries on. (The speaker worker already did this.)
- Tests: restart-once-then-error with a broken VAD step (exactly 2 attempts), failing decodes reported then cleared, ready-status wording for GPU / no GPU / failed GPU, translation keeps going after a buggy line. Suite 600.

## 2026-10-18 — User report: "Settings doesn't appear" and "minimizing makes the app disappear"
User's words: "the settings window doesn't appear when I click it from the right click menu. secondly whenever I minimize the app it disappears and there's no way for me to reboot it." Also "yes to all questions" (Qwen for Chinese on by default; Simplified; keep our language detector; push; restart).

**Settings.** Reproduced on the real app (restarted with stderr captured): Settings *did* open, but centred over the 635x715 pinned overlay. Pinned overlays are always-on-top, a normal window can't be above them, so Settings sat almost entirely hidden behind it. Nothing in the log; also found that under pythonw an exception in a menu slot would vanish without trace (no excepthook).
- Fix: Settings and Transcript get `WindowStaysOnTopHint` and, on first opening, are placed beside the first visible overlay (`geometry.beside`, same rule as Screen windows). Titles shortened to "Settings" / "Transcript" (Qt already appends " - Live Translator"; it read "Live Translator Settings - Live Translator").
- `app/log.install_excepthook`: uncaught errors are logged as type + file:line chain, never the message (could quote a line). Test proves "secret" text stays out.

**Minimize.** The chrome's "–" button was *hide*, not minimize: overlays are frameless Tool windows with no taskbar button, so the only ways back were Ctrl+Alt+H or the tray icon (Windows 11 puts it in the ^ overflow). Worse, Ctrl+Alt+H *toggled* hide-all: with the only window already hidden, the first press set hide-all and nothing visible happened.
- Probes (scratch scripts, real taskbar clicks via win.ps1): a frameless no-activate window minimized with `showMinimized` cannot be restored from the taskbar — with or without WS_EX_NOACTIVATE, with or without WS_MINIMIZEBOX|WS_SYSMENU it never received a message on the click. A plain Qt window restored fine (control). So: `ui/taskbar_button.TaskbarButton`, an invisible (opacity 0, 1x1) normal window kept minimized on the taskbar while any overlay is minimized. Clicking it (or its "Close window") restores the overlays and hides itself. First test run caught that hiding inside the WindowStateChange is undone by the restore's own show(); deferred with a 0 ms timer.
- Store owns it (single source of truth): `RuntimeState.away: dict[window id, Away.HIDDEN|MINIMIZED]`, actions `SetWindowAway`, `RestoreMinimized`; `SetAllHidden(False)` clears `away`; removing a window drops its entry. WindowManager's private `hidden` set is gone; visibility = not all_hidden and not away. Taskbar button must be hidden before quit (it refuses close events, which would cancel Qt 6's quit) — done in `close_all` and `_quit_now`.
- "Show/Hide all" (hotkey, tray item) now shows everything when *anything* is away, else hides all. Tray: a single click toggles (was double-click only; a single click did nothing). "Hide this window" shows a one-per-run notice saying how to bring it back.
- `SetCurrentProcessExplicitAppUserModelID("LiveTranslator.App")` so the taskbar button shows our icon/name instead of python.exe's. Side effect seen live: the notification header then said "LiveTranslator.App"; fixed by registering DisplayName + IconUri under HKCU (D-037), icon written to the data folder as app.ico.
- Single instance (`app/single_instance.py`, QLocalServer per user): starting the app again asks the running copy to show its windows (or open one) and exits. Test uses a real second process (same-thread client/server doesn't model it). Demo mode skipped.
- Desktop + Start-menu shortcuts "Live Translator" created for the user (pythonw -m livetranslator in the venv, app.ico), so they can start it without me.

**Defaults from the user's answers:** `EngineConfig.smart_languages` default `("zh",)` (Qwen for Chinese; game mode still turns it off). D-033 marked user-confirmed.
