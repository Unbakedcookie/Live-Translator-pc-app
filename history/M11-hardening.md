Pinned overlays are always-on-top, a normal window can't be above them, so Settings sat almost entirely hidden behind it. - Fix: Settings and Transcript get `WindowStaysOnTopHint` and, on first opening, are placed beside the first visible overlay (`geometry.beside`, same rule as Screen windows). Titles shortened to "Settings" / "Transcript" (Qt already appends " - Live Translator"; it read "Live Translator Settings - Live Translator").

**Minimize.** The chrome's "–" button was *hide*, not minimize: overlays are frameless Tool windows with no taskbar button, so the only ways back were Ctrl+Alt+H or the tray icon (Windows 11 puts it in the ^ overflow). Worse, Ctrl+Alt+H *toggled* hide-all: with the only window already hidden, the first press set hide-all and nothing visible happened.
- Probes (scratch scripts, real taskbar clicks via win.ps1): a frameless no-activate window minimized with `showMinimized` cannot be restored from the taskbar — with or without WS_EX_NOACTIVATE, with or without WS_MINIMIZEBOX|WS_SYSMENU it never received a message on the click. A plain Qt window restored fine (control). So: `ui/taskbar_button.TaskbarButton`, an invisible (opacity 0, 1x1) normal window kept minimized on the taskbar while any overlay is minimized. Clicking it (or its "Close window") restores the overlays and hides itself. First test run caught that hiding inside the WindowStateChange is undone by the restore's own show(); deferred with a 0 ms timer.
- Store owns it (single source of truth): `RuntimeState.away: dict[window id, Away.HIDDEN|MINIMIZED]`, actions `SetWindowAway`, `RestoreMinimized`; `SetAllHidden(False)` clears `away`; removing a window drops its entry. WindowManager's private `hidden` set is gone; visibility = not all_hidden and not away. Taskbar button must be hidden before quit (it refuses close events, which would cancel Qt 6's quit) — done in `close_all` and `_quit_now`.
- "Show/Hide all" (hotkey, tray item) now shows everything when *anything* is away, else hides all. Tray: a single click toggles (was double-click only; a single click did nothing). "Hide this window" shows a one-per-run notice saying how to bring it back.
- `SetCurrentProcessExplicitAppUserModelID("LiveTranslator.App")` so the taskbar button shows our icon/name instead of python.exe's. Side effect seen live: the notification header then said "LiveTranslator.App"; fixed by registering DisplayName + IconUri under HKCU (D-037), icon written to the data folder as app.ico.
- Single instance (`app/single_instance.py`, QLocalServer per user): starting the app again asks the running copy to show its windows (or open one) and exits. Test uses a real second process (same-thread client/server doesn't model it). Demo mode skipped.
